The operator requires verified backup, restore/rehearsal and regression evidence
before live apply. It refuses a different database GUID, changed baseline or seed.
No cleanup runs on startup. ddl-auto remains none. No passwords are changed.
Do not run apply a second time as a new reset. The seed batch is immutable: a repeat
of the SQL seed is a no-op; a conflicting manifest aborts instead of overwriting it.

Schema: migration-final-catalog.sql (additive/idempotent).
Data: reset-seed-final-catalog.sql and catalog-final-20261018.json.
Provenance: CATALOG_PRODUCT_PROVENANCE; manufacturer code may be NULL when only
retail size SKUs were published. No manufacturer code is inferred from those SKUs.
The preserved historical inventory backup table is recovery data, never live stock.

Inventory/sales determinism: seed 20261018. H(key) = unsigned big-endian integer
from the first eight bytes of SHA256(UTF8('20261018:' + key)). For each variant key,
rank stores 1..6 by H(variant + ':store:' + store). Carry the first
2 + H(variant + ':carried') % 3 stores. Quantities and simulated sales are validated
from the same algorithm by verify_final_catalog.py. Explicit zero rows mean tracked
but unavailable; missing rows mean not carried. Manager reorder level stays 10;
customer availability threshold stays 5.

DEMO_VARIANT_SALES contains explicitly simulated UNITS ONLY for [2026-09-01,
2026-10-18). No prices/revenue, customer identities, Orders or Payments are created.
Real soldCount/deliveredQuantity and all financial metrics still use transactions.
A separate demoSoldCount/demoQuantity is labeled 'Lượt bán mô phỏng'. Dashboard
and its Excel export select complete summary periods whose exclusive period_end
falls in the selected date window; no daily distribution is invented.

Rollback evidence: an outer transaction runs the entire data reset/seed and rolls
it back, then all table hashes are compared. SQL Server identities may advance
on rollback; keys are never reused or reseeded. Recovery backup location is recorded
locally in tmp/catalog-operations/recovery.json. Do not restore the live backup
blindly after new user transactions have occurred. Preserve it for controlled recovery.

Credentials are read into process environment, never command arguments or outputs.
Research/output CSVs and operational evidence stay in the Git-ignored docs folder.
No Git commit or push is performed by these tools.
